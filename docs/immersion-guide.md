# 몰입형 쇼츠 포맷 가이드

레퍼런스: https://www.youtube.com/shorts/q5C9HCN2QY4 (물속 다리 기둥을 세운 천재적인 해결법, 코퍼댐 공법의 진화)

레퍼런스에서 가져온 기본 전개는 **문제 → 해결 동작 → 새로운 난관 → 추가 해결 → 완성**입니다. 애니메이션은 멈추지 않고, 내레이션은 화면의 원인과 결과를 이어서 설명합니다. 이 가이드는 그 구조를 유지하면서 끝까지 보게 만드는 장치를 더합니다. 레퍼런스의 문장이나 화면을 복사하지 않습니다.

## 1. 대본 구조 (10문장 안팎, 원음 46초 이내)

1. **훅 (0~4초)**: **믿기 힘든 사실 + 과장된 반응어** 한 문장. 화면은 0프레임부터 이미 움직이고 있어야 합니다.
   - 예: "타워크레인이 자기 몸을 스스로 들어 올립니다. 처음 보면 제정신이 아닌 줄 알죠." / "~를 처음 보면 놀라 자빠집니다." / "~한다고요? 처음 들으면 제정신인가 싶죠."
   - 반응어 후보: 제정신이 아닌, 놀라 자빠질, 말도 안 되는, 미친 발상, 기가 막힌
   - 반응은 시청자 입장(처음 보면, 처음 들으면)으로 씁니다. "당시 사람들이 ~라고 했다" 같은 역사적 반응은 확인된 경우에만 씁니다.
   - 반응어 순간에 빠른 펀치인, 짧은 저음 히트, 크게 키운 노란 자막을 동시에 줍니다.
   - 같은 반응어를 연속 영상에서 반복하지 않도록 HANDOFF의 제작 이력에 사용한 표현을 남깁니다.
2. **오픈 루프 (2~5초)**: "그런데 ~를 어떻게 했을까요?" 같은 질문을 던지고, 답은 마지막 보상 문장에서만 줍니다.
3. **문제**: 왜 평범한 방법이 안 되는지 한 문장.
4. **해결 동작**: 2~3문장, 각 문장마다 화면의 물체 상태가 바뀝니다.
5. **새 난관**: "이제 진짜 문제는"처럼 명시적으로 선언합니다.
6. **추가 해결**: 단계별로. 가장 만족스러운 순간(압착, 맞물림, 안착)은 근접·슬로모션·묵직한 효과음으로 강조합니다.
7. **보상**: 오픈 루프에 대한 한 문장 답. 제목 1번 후보와 같은 말이면 좋습니다.
8. **완성·루프**: 마지막 프레임을 첫 프레임 구도와 맞춰 반복 재생이 자연스럽게 이어지게 합니다.

글자 수 기준: 공백 제외 약 6.5자가 원음 1초입니다. 280자 안팎이면 0.94 처리 후 약 45초로 끝나고 보상 장면을 위한 여유가 남습니다.

## 2. 화면 리듬

- 1초 넘게 정지한 화면이 없게 합니다. 최소 3초마다 새 샷이나 뚜렷한 상태 변화가 있어야 합니다.
- 전체 장면과 근접 장면을 교대합니다. 같은 샷 안에서도 카메라 시차를 유지합니다.
- 와이드 샷에는 크기를 알 수 있는 물체(사람, 차, 예인선)를 넣습니다.
- 숨은 원리는 X-ray 단면(수위, 압력 화살표, 내부 탱크)으로 보여 줍니다.
- 수면 위아래, 지상과 지하처럼 공간이 바뀔 때는 컷보다 카메라가 경계를 통과하는 연속 이동을 씁니다.

## 3. 화면 위 텍스트

- 텍스트는 화면 맨 위나 맨 아래가 아니라 **중앙보다 약간 위의 읽기 편한 영역**에 둡니다. 아이폰 상단과 쇼츠 UI(상단 아이콘, 하단 제목·채널, 오른쪽 버튼)에 가리지 않게 합니다.
- 0~300px: 텍스트 금지.
- 300~470px: 짧은 제목 한 줄과 진행 칩(① ② ③ ④). 지금 몇 단계인지 항상 보이게 합니다.
- 470~1250px: 주요 동작 영역. 카메라 구도의 중심.
- 1250~1450px: 자막 패널. Noto Sans CJK KR Bold, 3.8%, 폭 76% 이내, 최대 4어절·22자, 최대 두 줄.
- 1450px 아래와 오른쪽 버튼 열: 텍스트 금지.
- 주제 강조어는 노란색(#FFD400)으로 표시합니다. 나머지는 흰색에 어두운 외곽선입니다.
- **가로 정렬**: 제목, 진행 칩, 자막 각 줄, 영상 창은 모두 x=540 기준으로 정확히 가운데 정렬하고 좌우 여백을 대칭으로 둡니다. 최종 렌더 후 시작·중간·끝 프레임에서 텍스트 영역의 좌우 여백 차이가 2px 이하인지 측정합니다.

## 4. 소리

- 필재 음성이 항상 가장 크게 들립니다.
- 공간 전환(잠수, 지하 진입)에 맞춰 환경음의 질감을 바꿉니다.
- 핵심 순간(압착, 안착, 결합)에는 깊은 저음 한 번. 남발하지 않습니다.
- 생성 영상의 원래 오디오는 쓰지 않습니다.

## 5. 주제 고르는 기준

- 실제 공법 순서 안에 진짜 "새 난관"이 있는가.
- 원리를 숨김 없이 움직이는 모델로 보여 줄 수 있는가 (Blender로 정확히 제어 가능).
- 첫 2초에 보여 줄 압도적인 장면이 있는가.
- 마지막에 시원하게 풀리는 한 문장이 있는가.

## 6. 매 주제 산출물

`topics/<slug>/` 아래에 텍스트만 Git으로 관리합니다. 미디어는 `work/<slug>/`와 `outputs/`에 로컬 보관합니다.

- `brief.md`: 원리, 정확성 기준, 스토리 비트, 장면표
- `narration.txt`: 필재에 넣을 말만
- `title-description.txt`: 제목 후보 3개, 설명, 해시태그, 최종 대본
- `topic.json`: 생성 클립, 타임라인, 강조어, 주제별 검수 조건

새 주제는 `topics/_template/`을 복사해서 시작합니다.
