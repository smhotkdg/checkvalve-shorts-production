## 0. 포맷 고르기

**`principle_info` (보관된 대체 포맷):** 원리 하나를 단순한 그림으로 설명하고, 끝에 생활 속 정보 한 가지로 마무리합니다.
훅(통념 뒤집기 또는 놀라운 사실 + 반응어) → 질문 → 쉬운 비유 하나 → 원리 3~4단계(순환이나 순서) → 한 문장 정리 → **끝 정보**(원리에서 바로 나오는 의외의 생활 사실이나 팁) → 차분한 와이드 마무리.
- 끝 정보는 원리를 이해해야 납득되는 것으로 고릅니다. 예: 냉장고 문을 열어 둬도 방이 더워지는 이유.
- 제목 후보 1번은 끝 정보를 질문으로 만든 제목을 우선 검토합니다. 끝까지 보게 만듭니다.

**`problem_solution` (현재 기본):** 실제 난관이나 가상 비교에서 눈에 보이는 한계를 가진 기구 주제에 씁니다. 이번 앵커는 [주제 장면표](../topics/expansion-anchor/brief.md)가 우선입니다. 역사적 발전 과정으로 꾸미지 않습니다. 과장된 반응어를 반드시 넣을 필요는 없고, 빠지는 막대 자체가 훅이 될 수 있습니다.

## 1. `problem_solution` 대본 구조 (10문장 안팎, 원음 46초 이내)

1. **훅 (0~4초)**: **믿기 힘든 사실 + 과장된 반응어** 한 문장. 화면은 0프레임부터 이미 움직이고 있어야 합니다.
   - 예: "타워크레인이 자기 몸을 스스로 들어 올립니다. 처음 보면 제정신이 아닌 줄 알죠." / "~를 처음 보면 놀라 자빠집니다." / "~한다고요? 처음 들으면 제정신인가 싶죠."
   - 반응어 후보: 제정신이 아닌, 놀라 자빠질, 말도 안 되는, 미친 발상, 기가 막힌
   - 반응은 시청자 입장(처음 보면, 처음 들으면)으로 씁니다. "당시 사람들이 ~라고 했다" 같은 역사적 반응은 확인된 경우에만 씁니다.
   - 반응어 순간은 노란색과 짧은 저음 히트로 강조합니다. 주제별 카메라 규칙을 따르며 강한 펀치인과 큰 글자로 전체 구조를 가리지 않습니다.
   - 같은 반응어를 연속 영상에서 반복하지 않도록 HANDOFF의 제작 이력에 사용한 표현을 남깁니다.
2. **오픈 루프 (2~5초)**: "그런데 ~를 어떻게 했을까요?" 같은 질문을 던지고, 해결을 단계적으로 보여 주고 마지막에 원리와 용도를 정리합니다. 답을 숨기느라 화면 설명을 늦추지 않습니다.
3. **문제**: 왜 평범한 방법이 안 되는지 한 문장.
4. **해결 동작**: 2~3문장, 각 문장마다 화면의 물체 상태가 바뀝니다.
5. **새 난관**: "이제 진짜 문제는"처럼 명시적으로 선언합니다.
6. **추가 해결**: 단계별로. 가장 만족스러운 순간(압착, 맞물림, 안착)은 중간 거리 슬로모션과 묵직한 효과음으로 강조합니다.
7. **보상**: 오픈 루프에 대한 한 문장 답. 제목 1번 후보와 같은 말이면 좋습니다.
8. **완성·루프**: 마지막 프레임을 첫 프레임 구도와 연결할 수 있으면 연결합니다. 잠긴 구조가 저절로 풀리는 잘못된 동작으로 루프를 강제하지 않습니다.

글자 수 기준: 공백 제외 약 6.2자가 원음 1초입니다(타워크레인 실측 287자 = 46.15초). 280자 안팎이면 원음 약 45초입니다. 조금 길어지면 대사를 자르지 않고 영상을 늘립니다.

## 2. 한눈에 보이는 화면 (가장 중요)

2026-10-11 타워크레인 결과의 3D가 복잡하고 직관적이지 않았다는 피드백으로 정했습니다. 질감보다 **1초 안에 이해되는 그림**이 우선입니다. config의 `visual_clarity`가 기준입니다.

- **한 화면에 하나:** 지금 대사가 말하는 부분이 화면에서 가장 크고 밝고, 유일하게 뚜렷이 움직이는 대상입니다. 나머지는 멈춰 있습니다.
- **부품 최소화:** 원리 설명에 필요한 부품만 만듭니다. 격자, 볼트 줄, 케이블, 호스, 난간, 현장 소품처럼 반복되는 디테일은 그것이 원리일 때만 넣습니다.
- **색으로 역할 구분:** 고정 구조는 밝은 회색 무광, 물은 맑은 파랑, 주인공 하나만 주황(#FF7A1A). 대사에서 부품을 처음 말할 때 노란 테두리 빛을 약 1.5초 줍니다. 주제에 따라 온도처럼 색 자체가 의미인 경우 topic.json에 예외를 적습니다.
- **기본 시점 하나:** 전체 원리가 보이는 3/4 또는 옆 단면 시점을 영상의 60% 이상 씁니다. 시점은 최대 4개, 좌→우 방향은 끝까지 바꾸지 않습니다. 근접은 중간 거리로 3초 이내, 끝나면 기본 시점으로 돌아옵니다.
- **배경과 조명:** 부드러운 그라데이션 배경과 평평한 바닥, 밝고 고른 조명. 안개, 파티클, 렌즈 효과, 피사계심도, 어두운 장면은 쓰지 않습니다.
- **숨은 부분은 단면으로:** 자른 면은 단색, 위치는 영상 내내 고정합니다. 흐름이나 힘은 굵은 화살표 최대 2개로 보여 줍니다.
- **시청자가 따라갈 하나:** 열 알갱이, 수위선, 배처럼 눈으로 따라가면 원리가 이해되는 대상 하나를 정합니다.
- **크기 비교:** 와이드 샷에 사람 실루엣 하나(또는 차·배 하나)만 둡니다.
- **움직임:** 1초 넘게 정지한 화면이 없게 하고, 시작과 끝에 최소 0.4초 가속·감속을 둡니다. 강한 펀치인은 쓰지 않습니다.
- **생성 클립:** Higgsfield 클립도 승인된 Blender 프레임에서 시작하고 같은 단순한 모양·색을 유지합니다. 새 물체, 군중, 글자, 사실적인 잡동사니를 넣지 않습니다.
- **스타일 프레임 승인:** 전체 렌더와 유료 생성 전에 대표 프레임 3~4장을 사용자에게 승인받습니다. 각 장을 360px 흑백으로 줄여 무엇이 움직이는지 1초 안에 말할 수 있어야 합니다.

## 3. 화면 위 텍스트 (레이아웃 v4)

- 텍스트는 화면 맨 위나 맨 아래가 아니라 **중앙보다 약간 위의 읽기 편한 영역**에 둡니다. 아이폰 상단과 쇼츠 UI(상단 아이콘, 하단 제목·채널, 오른쪽 버튼)에 가리지 않게 합니다. 아래 수치는 1080×1920 제작 기준이며 모든 폰의 공식 safe area가 아닙니다.
- 화면 텍스트는 **고정 제목 하나와 자막뿐**입니다. 진행 칩, 단계 번호, 단계별 제목, 부품 이름표는 쓰지 않습니다(2026-10-11 사용자 요청).
- 0~500px: 텍스트 금지.
- 500~660px: 영상 내내 같은 짧은 제목 한 줄(56px 기준, 한국어 14자 이내). 중심 y=580.
- 660~1140px: 주요 동작의 중심. 원본 영상 전체를 잘라 넣는 창이 아닙니다.
- 1140~1380px: 자막. 블록 중심 y=1260, Noto Sans CJK KR Bold, 3.8%, 외곽선 포함 폭 74% 이내, 최대 4어절·22자·두 줄.
- **자막과 제목 뒤에는 배경 상자·띠·패널·블러를 두지 않습니다.** 흰 글자에 8px 어두운 외곽선과 부드러운 그림자로 읽히게 합니다. 그래도 읽기 어려우면 카메라 구도나 배경 밝기를 조정합니다.
- 1380px 아래와 오른쪽 버튼 열: 텍스트 금지.
- 가장 긴 두 줄 자막과 반응어를 시작·중간·끝 프레임과 함께 360px 폭에서 확인합니다. 상단 500px·하단 540px·오른쪽 UI 가림 마스크와 9:16·9:19.5·9:20 표시 예시로 중앙 가독성을 점검합니다.
- 주제 강조어는 노란색(#FFD400)으로 표시합니다. 나머지는 흰색입니다.
- **가로 정렬**: 제목과 자막 각 줄은 x=540 기준으로 정확히 가운데 정렬하고 좌우 여백을 대칭으로 둡니다. 최종 렌더 후 시작·중간·끝 프레임에서 글자 영역의 좌우 여백 차이가 2px 이하인지 측정합니다.

## 4. 소리

- 필재 음성이 항상 가장 크게 들립니다.
- 공간 전환(잠수, 지하 진입)에 맞춰 환경음의 질감을 바꿉니다.
- 핵심 순간(압착, 안착, 결합)에는 깊은 저음 한 번. 남발하지 않습니다.
- 생성 영상의 원래 오디오는 쓰지 않습니다.

## 5. 주제 고르는 기준

- 실제 공법 순서 안에 진짜 "새 난관"이 있는가.
- 원리를 숨김 없이 움직이는 모델로 보여 줄 수 있는가 (Blender로 정확히 제어 가능).
- 첫 2초에 보여 줄 압도적인 장면이나 뒤집을 통념이 있는가.
- **단순한 그림 몇 개로 설명되는가.** 부품이 많거나 복잡한 구조물은 피합니다.
- `principle_info`라면 끝에 줄 생활 속 정보가 있는가.
- 마지막에 시원하게 풀리는 한 문장이 있는가.

## 6. 매 주제 산출물

`topics/<slug>/` 아래에 텍스트만 Git으로 관리합니다. 미디어는 `work/<slug>/`와 `outputs/`에 로컬 보관합니다.

- `brief.md`: 원리, 정확성 기준, 스토리 비트, 장면표
- `narration.txt`: 필재에 넣을 말만
- `narration.en.txt`, `title-description.en.txt`: `en` 활성화 시에만 필요한 영어 세트(현재 생성하지 않음)
- `title-description.txt`: 제목 후보 3개, 화면 고정 제목, 설명, 해시태그, 최종 대본
- `topic.json`: 생성 클립, 타임라인, 강조어, 주제별 검수 조건

새 주제는 `topics/_template/`을 복사해서 시작합니다.

## 7. 장면 사이 연속성

물체의 배치·단면·조립 상태를 다음 컷에 전달합니다. 2~3초마다 의미 있는 동작을 설계하되 고정된 부품을 움직이게 만들지 않습니다. 접근→접촉→반응→안정 상태를 보여 주고, 움직이는 도구나 하중으로 고정 결과를 검증합니다. 은은한 질감·작은 베벨·부드러운 조명은 허용하되 복잡한 배경이나 거친 줌으로 구조를 가리지 않습니다. 원본의 검정 여백과 상단 제목 대신 기존 layout v4를 유지합니다.
